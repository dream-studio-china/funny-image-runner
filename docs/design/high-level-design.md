# 总体设计（High-Level Design）

## 1. 目标与范围

受邀用户使用有效邀请链接登录后，可反复使用同一个链接恢复登录；用户上传一张图片、按分类选择受控风格、填写允许的补充信息，目标流程为异步获得 ComfyUI 生成的图片。提供用户任务列表、状态、结果查看与下载，以及 `/admin` 邀请码、用户、分类和风格管理。管理员可在后台为分类/风格上传封面，并为风格填写 API 格式 workflow JSON、正向/负向 prompt 及固定 additional JSON；用户不能自由编辑这些私有配置或直接访问 ComfyUI。目标部署按单台 ComfyUI、单个常驻 worker 设计。当前已实现分类/风格配置、七牛直传、任务队列、Worker API 与本地 Worker 程序；真实生成需部署并配置 Worker 和 ComfyUI。

## 2. 部署单元

```text
用户浏览器 ── HTTPS ──> Vercel / Next.js (页面、Route Handlers)
      │                          │
      └── 直传/限时取图 ──> 七牛私有空间
                                 │
                         阿里云 RDS MySQL (持久化)
                                 ▲
                  HTTPS 主动轮询/回报 (worker 凭证)
                                 │
                   本地常驻 worker ── localhost:8188 ──> ComfyUI
                           │
                           └── HTTPS 下载输入/上传输出 ──> 七牛

管理员 ── 私有发码 CLI / 管理员 API ──> Vercel
管理员浏览器 ── `/admin` 管理后台 ──> Vercel
管理员 ── Tailscale (受限远程运维) ──> 本地机器
```

Next.js 同时承载页面与轻量 API。云端接口仅执行认证、校验、签名、数据库事务及状态查询，不承担图片字节转发或等待 GPU 完成。阿里云 RDS MySQL 是用户、邀请码、分类、版本化风格定义及任务的事实来源；七牛是用户图像及分类/风格展示图字节的事实来源。worker 只向外发起连接；ComfyUI 不对公网开放，浏览器无法调用 worker 内部接口。

若将来 worker 改部署到另一台机器，才需要通过 Tailscale grants 限制其到 ComfyUI 的主机/端口访问；当前同机配置使用回环地址。Tailscale 不代替用户登录或 worker API 凭证。

## 3. 主要流程

1. 管理员通过 `/admin` 或淘宝自动发货服务端签发邀请链接；CLI 可用私有 seed 在可信设备批量生成并导入。链接仅交付给对应用户。
2. 用户用邀请链接创建浏览器会话；同一链接在未过期、未撤销、用户未停用时可再次创建会话。`redeemed_at` 只记录首次使用时间。
3. 管理员维护分类、风格及封面；保存风格时将 workflow、prompt、negative prompt 和 additional JSON 记录为不可变版本。首页获取启用的分类及风格公开信息，展示分类封面并提供筛选；私有执行配置不随页面下发。
4. 用户请求某个图片 key 的限范围、短有效期上传凭证；浏览器直接上传七牛。
5. 用户提交 `preset_id`、`uploadId` 及白名单参数；云端核验上传对象和归属，锁定可执行的 `preset_id@version`，创建 `queued` 任务，立即返回 `job_id`。
6. 同机 worker 轮询领取任务，生成租约，按版本读取管理员配置的私有工作流，下载输入并上传到同机 ComfyUI；将受控参数写入工作流后提交 `/prompt`。
7. worker 等待并查询输出，将结果上传七牛，通过完成接口上报；用户轮询自己的任务，收到短期私有下载链接。

流程契约分别见 [身份](./low-level-identity.md)、[预设](./low-level-presets.md)、[存储](./low-level-storage.md)、[任务 API](./low-level-jobs.md)、[worker](./low-level-worker.md)。

## 4. 一致性与安全边界

- 所有浏览器 API 校验会话；`user_id` 从服务端会话读取，绝不信任请求中的自报标识。管理员、worker 各有独立凭证及路由权限。
- 邀请码是可重复使用至过期/撤销的登录凭证；数据库存摘要，自动发码 API 另存加密密文以支持幂等重发。CLI seed、服务端密钥均不进入浏览器包。
- 分类/风格在服务端做白名单校验；用户只能传公开参数，不能传节点 ID、模型路径、workflow JSON、正向/负向 prompt、additional JSON 或七牛任意 URL。执行配置仅由管理员保存且由 worker 受保护读取，按版本保留，历史任务不受后续编辑影响。
- 七牛对象按用户/任务区分 key；使用私有空间、限时签名链接和服务器端对象存在性检查；不允许通过用户提供的 URL 触发 worker 对任意内网地址下载。
- `POST /jobs` 返回任务 ID 而非等待推理；持久任务采用租约、心跳及尝试次数管理。ComfyUI 提交结果不明确时先对账，不能直接重放提交。
- `input`/`output` 只留存对象 key；结果归属由数据库任务记录决定。数据库索引、过期清理、重试与限额均须有独立实现。

## 5. 技术与容量基线

| 项目 | 首版决定 |
| --- | --- |
| Web | Next.js App Router、React、TypeScript、Tailwind CSS |
| 持久化 | 阿里云 RDS MySQL；短事务领取任务，不依赖 Vercel 进程内队列 |
| 图像存储 | 七牛私有空间；浏览器直传，worker 直下/直上 |
| 本地执行 | 独立 TypeScript/Node.js 常驻进程，同机调用 ComfyUI 原生 HTTP API |
| 实时性 | 浏览器短间隔轮询状态；worker 长轮询不作为首版前提 |
| 并发 | 单 worker、推理并发 1；Web 层按用户限额，后续再扩容 |

### 当前实现状态

- 已实现：`/admin` 管理会话、邀请码签发/撤销、用户启停、现有预设公开字段编辑；预设、用户、上传占位和任务存储于 MySQL。
- 已实现：登录用户经浏览器直传七牛并创建 `queued` 任务；用户任务列表/状态/结果访问 API 已有。
- 已实现：分类管理与首页筛选、分类/风格封面直传、弹窗新建/修改、风格私有 JSON 配置和不可变版本快照。旧风格迁入默认分类，旧任务关联保持不变。
- 已实现 Worker API 与独立本地 Worker 程序；只有配置并运行该 Worker、且 ComfyUI 与 workflow 正常时才会执行生成。Worker 在线状态展示、过期对象清理仍未实现。

数据库驱动采用 Drizzle ORM + mysql2，RDS 连接由 `DATABASE_URL` 配置；七牛 Kodo 通过服务端签名协议接入。限额、TTL 和文件大小均作为可配置值，首版建议值列在各详细设计中。

## 6. 验收链路

当前阶段验证：同一有效邀请码可重复登录、撤销/过期/停用后拒绝登录；管理员能管理用户、邀请和现有风格；跨用户无法查看任务；登录用户可直传七牛并创建 `queued` 任务。分类/风格升级阶段验证迁移保留历史记录、后台封面直传与 JSON 校验、公开分类筛选及私有配置隔离。worker 接入后再验证按历史版本执行、离线恢复、真实工作流产图、ComfyUI 报错恢复和结果短期链接权限。
